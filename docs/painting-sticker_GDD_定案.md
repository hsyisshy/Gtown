# 仿畫行動：拼貼修復版 — 定案記錄

> 本文件記錄原始 GDD 第 10 節「待確認 / 可調整項目」的定案結果，以及 Demo 階段的範圍調整。原始完整設計請參照團隊共用的遊戲設計文件。

## 1. 已定案項目（結構性決定）

| 項目 | 決定 | 備註 |
|---|---|---|
| 碎片存量隨時間減少機制 | **不需要** | 維持原核心設計：碎片有限＋搶奪＋5 分鐘倒數即可製造時間壓力，不加額外機制 |
| 攻擊型道具（暈眩／震動／強光）取得方式 | **隨機混入碎片架** | 與一般碎片一起用既有抓取操作取得，不加額外道具欄位或介面 |
| 「查看原畫」道具取得方式 | **混入碎片架取得** | 與攻擊型道具取得方式一致 |
| 正式版（多人連線）隊伍人數 | **暫不決定** | 待 Demo 驗證好玩度後，再定 2v2 或 3v3；Demo 之後再往該規格加多人連線 |

## 2. Demo 階段範圍調整

| 項目 | 決定 | 備註 |
|---|---|---|
| 電腦對手邏輯 | **不跑真邏輯，用假資料頂著** | 電腦端畫布直接顯示一個寫死／預錄的最終畫面，不即時模擬抓取／放置行為 |
| 真人玩家游標數量 | **1 支** | 先驗證單人抓取／放置／計分的核心操作迴圈；「同隊多人共用畫布、多游標互相干擾」（原文件 3.3～3.6 節）留待正式版多人連線時再實作 |

## 3. 數值型參數（Demo 預設值，需配合真人測試調整）

| 參數 | 預設值 | 備註 |
|---|---|---|
| 碎片數量與破碎程度 | 由美術素材決定 | 由原畫／碎片／metadata 提供者決定，不在此預先定案 |
| 容錯範圍（座標偏移多少內算「正確」） | 碎片中心點實際位置與正確位置的像素距離 ≤ 碎片平均邊長的 30% 給滿分；超過後線性遞減；超過 2 倍邊長鎖 0 分 | 純技術定義的計分曲線，需配合實測手感調整門檻與遞減曲線形狀 |
| 暈眩持續時間 | 2.5 秒 | 原文件暫定 2-3 秒，取中間值 |
| 震動效果 | 已放置碎片隨機位移碎片尺寸的 ±15%，不會自動歸位，需玩家人工重新對位 | |
| 強光效果 | 曝曬畫布約 1/4 區域，持續 4 秒 | |
| 開場原畫預覽時長 | 10 秒 | 維持原文件設定 |
| 「查看原畫」道具效果 | 使用後再看 5 秒原畫 | |
| 道具碎片混入比例 | 佔碎片架總碎片數的 10%，四種道具（暈眩／震動／強光／查看原畫）均分 | |

## 4. 資產資料夾結構（畫廊式，支援多幅原畫）

```
Painting2/
└── Assets/
    └── Paintings/
        ├── painting_01/        ← 目前已放素材的第一幅畫
        │   ├── Raw/             原畫（完整原圖）
        │   ├── Pieces/          碎片透明背景 PNG
        │   ├── Pieces_backup/   修復前的原始碎片備份
        │   └── Meta/            metadata.json（每片碎片正確座標、道具標記等）
        ├── painting_02/         ← 空的，等你放第二幅畫素材
        │   ├── Raw/
        │   ├── Pieces/
        │   └── Meta/
        └── painting_03/         ← 空的，等你放第三幅畫素材
            ├── Raw/
            ├── Pieces/
            └── Meta/
```

`painting_01/02/03` 目前是佔位資料夾名稱，之後可依實際畫作標題改名（改資料夾名不影響內容，遊戲讀取時建議以資料夾名稱本身作為畫作 ID）。若要準備第 4 幅以上，直接新增同結構的 `painting_04/` 即可。
